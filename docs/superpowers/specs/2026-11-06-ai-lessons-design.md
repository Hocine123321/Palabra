# Books: AI-authored, editable lessons ("Lesson Studio")

Status: written 2026-11-06 from the user's brief; the user asked to go straight to design, plan and execution, so the
open choices below are the author's calls (marked **Call**) and can be reversed.

## Intent

Lessons are hardcoded JSON bundled with the app, and there is no way to add one. The person wants to add lessons from
photos of his notebook (or pasted text) inside the app, with AI that only **polishes the presentation** of the raw text
(no content of its own, as accurate as possible), to change the parts he does not like by asking, and then to **edit the
result live on the 2D book pages**. The 3D books always read from the 2D books' data, so a saved or edited lesson shows
up on the desk with no extra step.

## Goals

- **Lesson Studio**: a chat-styled screen (same look and feel as the Spanish chat, different purpose) per book. Input: one or
  more photos (library or camera) and/or pasted text. Output: a lesson built from the app's existing block types.
- **Two-step AI**, so accuracy can be checked: (1) *transcribe* each photo to raw text, shown to the person and editable
  (what the AI read, with doubtful spots listed); (2) *format* the raw text into a lesson. Typed/pasted text skips step 1.
- **Faithfulness gate**: the formatted lesson may not contain a number or date that is not in the raw text; other new words
  raise a visible warning. A failing lesson gets one automatic retry with the concrete problem, then is shown with the
  warnings. Illegible or ambiguous source text goes to `transcriptionNotes`, never guessed.
- **Change by asking**: follow-up messages ("make page 2 a timeline", "remove the quote") revise the draft; each revision
  goes through the same validation and faithfulness gate.
- **Live editing on the 2D pages**: an Edit mode in the reader: edit a block's text and fields, add, delete and reorder
  blocks and pages, retitle a page, rename or delete a lesson. Changes are saved as you go.
- **One source of truth**: lessons live in a writable on-device store; the 2D reader and the 3D desk both read it through
  `BookLibrary`. The existing bundled lesson is copied into the store once, so it becomes editable too.

## Non-goals

- No image blocks produced by the AI (images need asset-catalog names); no OCR outside Gemini; no cloud sync.
- No change to the 3D scene's rendering code; no new block types.
- Not turning Palabra into a general note editor: only lessons in the two books.

## Anti-goals

- AI-added facts, "helpful" explanations, invented dates or definitions. A lesson that looks better but says something new is a failure.
- Silent loss of the person's edits when the AI revises: a revision is a draft until saved, and saved edits are never overwritten by AI output without Save.
- Page ids changing under saved reading progress (pages keep their ids across edits and revisions).

## Constraints

- Gemini only, through the existing `AIClient`: `generateJSON(prompt:image:…)` takes ONE image, so each photo is its own
  transcription call (no protocol change, so no new `MockAIClient` stubs). Photos go through `PhotoPreparer` like the chat.
- Lesson JSON is the existing format (`docs/features/books.md`); `LessonValidator` is the structural gate. Lesson id and
  page ids never contain "/".
- File names in the store are `<lesson id>.json`; ids are generated by the app (slug + short suffix), never by the AI.
- Everything works offline except the AI steps; editing needs no network.
- Repo rules: UI strings need Arabic keys; AGENTS.md and `docs/features/books.md` must stop saying "no AI in Books".
- Compiled by eye only here; CI is the compiler.

## Approaches considered

1. **JSON files in Application Support behind `BookContentSource` (chosen).** A `LessonStore` owns `catalogue.json` and
   `lessons/<id>.json`; `BookLibrary.load` and `LessonValidator` stay as they are, the 3D desk is untouched.
2. Lessons in SwiftData. Rejected: new schema and migration for data that is already JSON, and the loader/validator would be rewritten.
3. Keep bundled JSON and have the AI output JSON for the developer to commit. Rejected: the person wants this inside the app.

## Design

- **Models**: make `Lesson`, `LessonPage`, `Block` and the item structs `Encodable` (round trip with the existing decoder).
- **`LessonStore`** (`Features/Books/Storage`): directory `Application Support/Books/`. `seedIfNeeded(from: BookContentSource)`
  copies the bundled catalogue and lessons once (recorded in `seeded.json`, so a deleted lesson is not resurrected).
  API: `catalogueData()`, `lessonData(file:)` (it is a `BookContentSource`), `save(lesson:bookID:chapterID:)`,
  `delete(lessonID:)`, `addChapter(bookID:title:) -> String`, `renameChapter`, `lesson(id:) -> Lesson?`.
  Writes are atomic. `BookShelf` is created with this store as its source and gets `libraryVersion` (bumped on every store
  change after `reload()`); the desk screen rebuilds when it comes back on screen with a newer version.
- **`LessonFaithfulness`** (pure): `check(lesson:, source:) -> Report { blockedNumbers: [String], newWords: [String] }`;
  digits are normalized (Arabic-Indic and Persian digits to Western) and compared as digit runs; words of 3+ letters are
  compared after stripping Arabic diacritics and the leading definite article/prefixes; `newWords` is a warning only.
- **`LessonPrompts` / `LessonAuthor`** (`Features/Books/AI`): `transcribe(photo:)` -> `{text, uncertain[]}`;
  `format(rawText:, book:, instruction:)` -> `Lesson`; `revise(current:, rawText:, instruction:)` -> `Lesson`. All use
  `generateJSON` with `schema: nil`, `CodeFence.extractJSON`, decode `Lesson`, run `LessonValidator` and `LessonFaithfulness`,
  retry once with the concrete problems. Ids are assigned by the app after decoding (`LessonIDs.assign`): the lesson id
  from the title slug (unique in the book), page ids kept from the previous version by position on revisions, `p1…` otherwise.
  The system prompt copies the block catalogue and the rules from `books.md` ("Rules for the author") and adds: use only
  the source text; do not explain, summarize, translate or complete; put doubts in `transcriptionNotes`; keep the source language.
- **Lesson Studio UI** (`Features/Books/Studio`): `LessonStudioSession` (observable: messages, attachments, raw text,
  draft, report, phase) and `LessonStudioView`: chapter picker (existing or new), message list with "What I read"
  (editable), "Draft" (page previews using `BookPageView`), warnings, composer with photo/camera/text, Save to book.
  Entry: "Add lesson" in `BookDetailView`'s toolbar and in the 2D book list.
- **Live editing** (`Features/Books/Editing`): `LessonEditor` (pure value operations: update/insert/delete/move block,
  add/delete/move page, set page title/dateLabel, rename lesson; each returns a new `Lesson` that still passes
  `LessonValidator`) and `BlockEditorView` (form per block type). `BookReaderView` gets an Edit toggle; edits call
  `environment.books.saveLesson(...)`, which writes the store, reloads the library and keeps the reader on the same page id.
- **Delete lesson / rename chapter** from `BookDetailView` (swipe and menu), with confirmation.
- **Backup**: user lessons are included wherever `Core/Backup` collects app data if it already enumerates files; otherwise noted in `docs/REVIEW.md` as a follow-up.

## Calls (reversible)

- Transcription is a separate, editable step (accuracy over one-tap convenience); typed text skips it.
- The bundled lesson is copied into the store once and becomes editable; the bundle remains only as the seed.
- One lesson per Studio session; chapter chosen or created in the Studio.
- Faithfulness: numbers are a hard gate after one retry; new words are warnings.

## Left to the builder

Exact visual layout of the Studio, the form fields of each block editor, wording of warnings, Arabic strings.

## Tests

Round-trip encode/decode of every block type; `LessonStore` seeding, save, delete, chapter add, atomicity on a temp dir,
`BookLibrary.load` over the store; `LessonFaithfulness` (numbers in Arabic-Indic digits, new numbers blocked, new words warned,
source-only content passes); `LessonAuthor` with `MockAIClient` asserting the actual request prompt/system text and the image
bytes sent, retry on validator or faithfulness failure, id assignment keeping page ids; `LessonEditor` operations keep the
lesson valid; `LessonStudioSession` flow with a stub client; localization test for new keys. JavaScript/3D rendering is not
covered; the 3D refresh is covered by a `BookShelf.libraryVersion` unit test.
